# 2026-10-19 学習メモ：API・Webhook・MCP・GAS

## 今日のまとめ（3行）

1. **仕組み**：API は人間が聞く、Webhook は向こうが教える、MCP は AI が自分で取りに行く。GAS でつないで、もっと大きくするなら AWS。
2. **作り方**：固定のものはツール（API・GAS）、固定じゃないものはスキル（AI への指示書）。伸びてる投稿と伸びていない投稿をセットで AI に渡す。
3. **目的**：再現性を高める。運で伸びた投稿を、狙って伸ばせるようにする。

## ひとことで

| 仕組み | 誰が動く？ | イメージ |
| --- | --- | --- |
| **API** | 人間（またはプログラム）が聞きに行く | 「承認」ボタンを押す → API を呼ぶ → 処理や連絡が飛ぶ |
| **Webhook** | 相手側から知らせが飛んでくる | 「何か起きたら、このURLに教えてね」と登録しておく |
| **MCP** | AI が自分で取りに行く | AI が必要な情報やツールを判断して使う |
| **GAS** | 上の仕組みをつなぐ道具 | Google のサービス上で動く自動化スクリプト |

## API（Application Programming Interface）

- アプリ同士が会話するための「窓口」。
- **こちらから聞きに行く（リクエスト）→ 答えが返る（レスポンス）**。
- 例：承認ボタンを押す → API を呼ぶ → Slack やメールに連絡が飛ぶ。
- きっかけを作るのは人間（またはプログラム）。

## Webhook

- **イベントが起きたら、相手から自動で知らせてくれる**仕組み。
- 「逆向きの API」とも言われる。こちらは待っているだけでいい。
- 例：フォームが送信された／支払いが完了した → 登録したURLに通知が届く → 連絡を飛ばす。
- API：こちらから何度も「まだ？」と聞く（ポーリング）
  Webhook：起きた瞬間に向こうから教えてくれる（プッシュ）

## MCP（Model Context Protocol）

- **AI が外部のツールやデータに自分でアクセスするための共通ルール**。
- 人間が「これ調べて」と細かく指示しなくても、AI が必要に応じて
  カレンダー・ファイル・GitHub などを自分で見に行ける。
- API が「人間が聞く窓口」なら、MCP は「AI が聞くための窓口」。

## GAS（Google Apps Script）

- Google が提供する、ブラウザだけで書ける JavaScript ベースのスクリプト環境。
- スプレッドシート・Gmail・フォーム・カレンダーなどを自動化できる。
- 外部の API を呼んだり、Webhook の受け口（`doPost`）を作ったりもできる。
- 例：フォーム送信 → GAS が動く → Slack に通知 → スプレッドシートに記録。

## AWS（Amazon Web Services）＝ GAS の一段上

- Amazon のクラウドサービス。サーバーや AI など、いろいろな部品を組み合わせて使う。
- GAS は「Google の中で手軽に自動化」。AWS は「もっと大きく、本格的に自動化」。

| | GAS | AWS |
| --- | --- | --- |
| 始めやすさ | ◎ ブラウザだけですぐ書ける | △ 設定・権限・料金の管理が必要 |
| 料金 | 無料 | 使った分だけ（無料枠あり） |
| 1回に動ける時間 | 約6分まで | Lambda なら最大15分。さらに長い処理もできる |
| 扱える量 | 少なめ（1日の回数制限あり） | 大量でも OK |
| できること | Google のサービスの自動化が中心 | 動画の文字起こし、AI、データベースなど何でも |

- まず GAS で作る → 限界が来たら AWS に移す、が王道。



```
[人間] --押す--> API ------> 処理・連絡       （人間が聞く）
[イベント発生] --> Webhook --> 通知が飛んでくる （向こうが教える）
[AI] --自分で--> MCP ------> ツール・データ   （AIが聞く）
          GAS = これらをつないで自動化する道具
          AWS = GAS の一段上。大きく・本格的に動かすときに使う
```

## 再現性を高める（API とのつながり）

- **再現性**＝誰がやっても、何回やっても、同じくらいの結果が出ること
- **API** は「決まった形で頼むと、決まった形で返ってくる」窓口。だから固定の作業をツールにできる
- データ（API）と計算（ツール）は毎回同じ。ばらつくのは AI の解釈の部分だけ
- AI のばらつきは、指示書（スキル）・良い例と悪い例・答えの形の指定・温度の設定で抑える
- 最後は自分が体験を足して、内容に責任を持つ

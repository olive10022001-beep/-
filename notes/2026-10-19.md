# 2026-10-19 学習メモ：API・Webhook・MCP・GAS

## ひとことで

| 仕組み | 誰が動く？ | イメージ |
| --- | --- | --- |
| **API** | 人間（またはプログラム）が聞きに行く | 「承認」ボタンを押す → API を呼ぶ → 処理や連絡が飛ぶ |
| **Webhook** | 相手側から知らせが飛んでくる | 「何か起きたら、このURLに教えてね」と登録しておく |
| **MCP** | AI が自分で取りに行く | AI が必要な情報やツールを判断して使う |
| **GAS** | 上の仕組みをつなぐ道具 | Google のサービス上で動く自動化スクリプト |

## API（Application Programming Interface）

- アプリ同士が会話するための「窓口」。
- **こちらから聞きに行く（リクエスト）→ 答えが返る（レスポンス）**。
- 例：承認ボタンを押す → API を呼ぶ → Slack やメールに連絡が飛ぶ。
- きっかけを作るのは人間（またはプログラム）。

## Webhook

- **イベントが起きたら、相手から自動で知らせてくれる**仕組み。
- 「逆向きの API」とも言われる。こちらは待っているだけでいい。
- 例：フォームが送信された／支払いが完了した → 登録したURLに通知が届く → 連絡を飛ばす。
- API：こちらから何度も「まだ？」と聞く（ポーリング）
  Webhook：起きた瞬間に向こうから教えてくれる（プッシュ）

## MCP（Model Context Protocol）

- **AI が外部のツールやデータに自分でアクセスするための共通ルール**。
- 人間が「これ調べて」と細かく指示しなくても、AI が必要に応じて
  カレンダー・ファイル・GitHub などを自分で見に行ける。
- API が「人間が聞く窓口」なら、MCP は「AI が聞くための窓口」。

## GAS（Google Apps Script）

- Google が提供する、ブラウザだけで書ける JavaScript ベースのスクリプト環境。
- スプレッドシート・Gmail・フォーム・カレンダーなどを自動化できる。
- 外部の API を呼んだり、Webhook の受け口（`doPost`）を作ったりもできる。
- 例：フォーム送信 → GAS が動く → Slack に通知 → スプレッドシートに記録。

## 流れのまとめ

```
[人間] --押す--> API ------> 処理・連絡       （人間が聞く）
[イベント発生] --> Webhook --> 通知が飛んでくる （向こうが教える）
[AI] --自分で--> MCP ------> ツール・データ   （AIが聞く）
          GAS = これらをつないで自動化する道具
```
